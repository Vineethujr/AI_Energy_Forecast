# Project notes

## Research question
Can recent consumption history, hourly/weekly patterns, and rolling averages provide useful short-term forecasts of hourly building energy usage?

## Data contract
- `timestamp`: date/time for the observation
- `energy_kwh`: energy consumed during the corresponding hourly interval, in kWh
- One observation per hour is expected; duplicate timestamps are reduced to the last record before resampling.

## Why chronological evaluation?
Energy forecasting is a time-series task. Training on later timestamps and testing on earlier timestamps can give an overly optimistic estimate. This project trains on the earlier 80% and tests on the later 20%.

## Limitations
The default dataset is synthetic and generated by a formula with noise. It does not represent any particular customer or utility. Metrics from synthetic data demonstrate that the pipeline executes; they are not evidence of real-world accuracy. For real evaluation, document dataset provenance, units, sampling interval, missing-data handling, and date range.

## Suggested extension experiments
1. Compare with a seasonal-naive forecast (`energy at t-24`).
2. Compare Random Forest with Linear Regression and HistGradientBoostingRegressor.
3. Add temperature or calendar-holiday features if available.
4. Use rolling-origin cross-validation and report metrics across multiple windows.
5. Add unit tests for schema validation, feature leakage, and API input validation.
